# Security and privacy

## Controls implemented

| Requirement               | Implementation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Password handling         | Better Auth with scrypt hashing. Minimum 10 / maximum 128 characters. Changing or resetting the password revokes other sessions                                                                                                                                                                                                                                                                                                                                                                            |
| Sessions & cookies        | Database-backed sessions (revocable), 14-day expiry with daily refresh. `HttpOnly`, `SameSite=Lax`, `Secure` in production, `dalali` cookie prefix                                                                                                                                                                                                                                                                                                                                                         |
| Server-side authorization | `src/server/actor.ts` assertions inside every service. Role and status are re-read from PostgreSQL on every request. Admin pages also check at page level, but security never depends on that                                                                                                                                                                                                                                                                                                              |
| Privilege escalation      | `role`/`status` are Better Auth `input: false` fields. The sign-up role is limited to TENANT/LANDLORD/AGENT, applies only to brand-new accounts and cannot be replayed. ADMIN comes only from the CLI or an existing admin. Admins cannot change their own role or suspend themselves, and cannot review their own verification or moderate their own listing                                                                                                                                              |
| IDOR                      | Ownership checks return _not found_ (not _forbidden_) so other users' IDs are not confirmed. Evidence downloads are limited to the submitter or an admin. Viewing requests are scoped to requester or advertiser                                                                                                                                                                                                                                                                                           |
| Mass assignment           | Zod schemas whitelist fields. Services build Prisma `data` explicitly, so status, slug, advertiser, publication dates etc. can never come from input (covered by tests)                                                                                                                                                                                                                                                                                                                                    |
| Input validation          | Zod on the server for all inputs. PostgreSQL CHECK constraints as a second layer                                                                                                                                                                                                                                                                                                                                                                                                                           |
| SQL injection             | Prisma query builder. The only raw SQL (rate limiting, test truncation) uses tagged-template parameters or fixed identifiers                                                                                                                                                                                                                                                                                                                                                                               |
| XSS                       | React escaping. No `dangerouslySetInnerHTML`. User text rendered as plain text. Strict CSP (see below)                                                                                                                                                                                                                                                                                                                                                                                                     |
| CSRF                      | Server Actions have Next.js's built-in Origin/Host check. Better Auth checks Origin against `trustedOrigins`. State-changing endpoints are POST-only. `SameSite=Lax` cookies                                                                                                                                                                                                                                                                                                                               |
| Open redirects            | `safeNext()` only allows same-site relative paths                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Rate limiting             | PostgreSQL-backed atomic fixed-window limiter shared by Better Auth (sign-in 8/5 min, sign-up 6/h, reset 5/h…) and the app (reports 10/h, viewing requests 15/h, uploads 60/h, listing writes 60/h, feedback 10/h, verification submissions 10/day). Keys use HMAC-hashed IPs or user IDs. Behind a proxy (`TRUST_PROXY_HEADERS=true`), the IP comes from `CLIENT_IP_HEADER` (a header the edge sets itself, e.g. `cf-connecting-ip`) before the first `X-Forwarded-For` entry, which a visitor can supply |
| File uploads              | Magic-byte detection (JPEG/PNG/WebP/PDF only), 8 MB per file, count limits, sharp re-encoding (removes EXIF/GPS and neutralises malformed images), random storage keys, path-traversal guard                                                                                                                                                                                                                                                                                                               |
| Private documents         | Never under `public/`. Served by `/api/evidence/:id` and `/api/report-evidence/:id` after authorization, with `Cache-Control: private, no-store`, `nosniff`, a sandboxing CSP and same-origin CORP. Admin views are audit-logged                                                                                                                                                                                                                                                                           |
| Errors                    | `runAction()` returns only `AppError` messages. Other errors are logged on the server and replaced by a generic message. Error boundaries show only a digest reference                                                                                                                                                                                                                                                                                                                                     |
| Security headers          | CSP, HSTS (production), `X-Frame-Options: DENY`, `frame-ancestors 'none'`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`, COOP. `X-Powered-By` disabled                                                                                                                                                                                                                                                                                                                                               |
| Secrets                   | Configuration validated at startup. `.env` is git-ignored, and `.env.example` holds placeholders only                                                                                                                                                                                                                                                                                                                                                                                                      |
| Audit                     | `audit_log` records sign-ups, listing and moderation changes, verification decisions and evidence views, role changes, suspensions, deletions and scheduled jobs. Metadata is sanitised (keys such as password, token, secret, NIDA or document are redacted)                                                                                                                                                                                                                                              |
| Data minimisation         | Optional phone numbers. Approximate coordinates rounded to ~100 m. Analytics without identifiers. Evidence purged `EVIDENCE_RETENTION_DAYS` after a decision. Account self-deletion anonymises the user and deletes their files                                                                                                                                                                                                                                                                            |

### Content Security Policy note

Next.js injects inline bootstrap scripts, so `script-src` includes `'unsafe-inline'`. To tighten this further, adopt nonce-based CSP through `proxy.ts` (Next 16 middleware), at the cost of making every page fully dynamic. All other directives are restrictive (`default-src 'self'`, no objects, no framing, `form-action 'self'`). The only third-party resource is the optional OpenStreetMap embed.

## Retention policy (defaults)

| Data                           | Retention                                                                                                                 |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| Verification evidence files    | Deleted 180 days after a decision (`EVIDENCE_RETENTION_DAYS`), or immediately on account deletion. Decision metadata kept |
| Report evidence                | Kept while the report is open. Deleted on account deletion of the uploader. Define a purge period with counsel            |
| Accounts                       | Until deleted by the user. Deleted accounts are anonymised and moderation records kept                                    |
| Sessions                       | Expire after 14 days of inactivity                                                                                        |
| Audit log / moderation actions | Kept for accountability. Agree a retention period with counsel (e.g. 5 years)                                             |
| Analytics events               | No personal data. Can be aggregated or pruned after 13 months                                                             |
| Backups                        | Follow the database provider's retention; see DEPLOYMENT.md                                                               |

## Before collecting identity documents in production

1. Have a Tanzanian lawyer review the privacy policy and terms, and confirm obligations under the **Personal Data Protection Act, 2022** (for example registration with the Personal Data Protection Commission, lawful basis, cross-border transfer rules if storage or hosting is outside Tanzania, and data-subject rights).
2. Define who your reviewers are, train them (see OPERATIONS.md), and restrict administrator accounts to them.
3. Use a private S3-compatible bucket with public access blocked, encryption at rest and access logging. Choose a region consistent with your legal advice.
4. Enable two-factor authentication for administrators (Better Auth's `twoFactor` plugin) before onboarding external reviewers. It is not yet enabled in the MVP.

## Known limitations / follow-ups

- No 2FA for administrators yet (see above).
- Uploaded files are not virus-scanned. Images are re-encoded, but PDFs are stored as-is and served with `Content-Disposition: attachment` plus a sandboxing CSP. Add ClamAV or a provider scan before scaling.
- `listing_view` counts can be inflated by bots, so treat them as indicative only.
- Email verification of new accounts is not enforced (no email provider is required for MVP testing). Enable `requireEmailVerification` once email is configured.
- Phone numbers are not verified by OTP.
